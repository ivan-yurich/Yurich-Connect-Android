# Диагностика На Телефоне За 7 Дней

Режим записывает наблюдения на самом Android-устройстве. Компьютер и USB
для записи не нужны. Это диагностика обычного использования, а не автотест,
который сам переключает серверы, отключает интернет или включает VPN.

## Запуск

1. Открыть Yurich Connect, развернуть раздел «Логи».
2. Включить «Диагностика на 7 дней» и подтвердить локальную запись.
3. Проверить дату окончания и пользоваться телефоном как обычно.
4. Для сравнения самостоятельно выбирать нужные профили, пользоваться
   Wi-Fi и LTE, оставлять телефон заблокированным. Никакой профиль режим
   диагностики не включает автоматически.

Запись выключена по умолчанию. Срок отсчитывается от подтверждения запуска.
Каждое наблюдение проверяет срок; после его истечения новые рабочие события
не записываются. Для окончания режима телефон специально не пробуждается.
На одном запуске устройства используется также elapsed realtime, чтобы
перевод часов назад не продлевал запись. После перезагрузки используется
системная дата; не переводить часы вручную во время проверки.

В разделе видны дата начала и дата окончания записи. «Не запущена» означает,
что текущего периода нет; ошибка чтения показывается отдельно. Ранняя остановка
помечается «Остановлена досрочно», а не выдаётся за полную неделю наблюдений.

## Что Записывается

- Состояние нативного VPN, поколение сессии, PID/экземпляр сервиса и TUN.
- Результаты существующего HTTPS-quorum; устаревшие результаты отмечены.
- Категория отказа endpoint: TLS, timeout, CONNECT/HTTP, I/O; длительность.
- Смена физической сети, screen-on, unlock, Doze и запросы перезапуска.
- Отдельно: принятый запрос восстановления, recycle процесса и отложенное
  восстановление по ограничению повторов. Пауза автоматических перезапусков
  увеличивается при длительных отказах; это не считается успешной проверкой.
- Память процесса, байты UID, температура/заряд батареи, состояние экрана.
- Категория необработанной Flutter-ошибки, без текста исключения.
- Доступная системная история завершений собственных процессов: причина,
  время, память, crash/native crash/ANR. Эта история доступна с Android 11.

Ресурсы собираются не чаще одного раза в 5 минут на процесс, по существующим
событиям/watchdog, и при явном запуске режима. Нового постоянного таймера,
сервиса, сетевых запросов или wake lock для диагностики нет.

Профили обозначаются токеном из хеша конфигурации, зависящим от текущего
запуска диагностики. В журнал не попадают исходные конфигурации, UUID,
пароли, URL подписок, названия/адреса серверов, SSID или посещённые сайты.
Сырые сообщения logcat и traceInputStream ANR не экспортируются, поскольку
они могут содержать секреты. Токен нужен лишь для сопоставления наблюдений.

## Хранение И Ограничения

Хранилище: отдельная SQLite DB в приватном `noBackupFilesDir`. Существующая
база профилей, URI-схемы и VPN API не меняются. Диагностический MethodChannel
добавлен только внутри приложения; внешнего broadcast/HTTP управления нет.

- Не более 40 000 записей; старые строки ротируются, число ротаций явно
  включено в метаданные. SQLite DB ограничена 32 MiB; WAL может временно
  занимать дополнительное место до checkpoint.
- Очередь I/O ограничена 256 элементами. Пропуски очереди и ошибки записи
  учитываются отдельно от сетевых отказов. Диагностика не блокирует VPN.
- При остановленном/усыплённом процессе нет текущих наблюдений. При следующем
  запуске или экспорте собирается доступная история exit-info; она тоже
  ограничена Android и не гарантирует наличие всех прошлых завершений.
- Удаление приложения и очистка его данных уничтожат журнал. Обновление
  той же подписанной сборкой обычно сохраняет данные, но для этой недели
  лучше не менять тестируемую версию.
- Отсутствие записанного crash не доказывает отсутствие ошибок. Это не
  подтверждение стабильности 24/7 или прохождения всех протоколов.

## Выгрузка

После недели подключить телефон к компьютеру. В «Логи» нажать значок
сохранения рядом с режимом, выбрать локальную папку Download через системный
выбор файла. Получится `YurichConnect-diagnostics-7days.zip`. По умолчанию
данные никуда не отправляются. Ручной выбор облачного провайдера в системном
диалоге является отдельным действием пользователя.

ZIP содержит `metadata.json` и `events.jsonl`. Отчёт остаётся на телефоне
после окончания срока и после ранней остановки переключателем. Новый запуск
становится текущим отчётом; перед ним экспортировать предыдущий.

Разбор скопированного на компьютер архива из корня репозитория; нужен Python 3:

```powershell
python .\tooling\analyze_device_diagnostics.py .\YurichConnect-diagnostics-7days.zip --output .\build\qa\seven-day-summary.json
```

Анализатор не извлекает произвольные пути из ZIP, проверяет структуру,
размер и полноту snapshot. Считает quorum, серии отказов, наблюдавшиеся
экземпляры VPN, запросы перезапуска, crash/ANR, ресурсы и пропуски. Он не
засчитывает паузы наблюдений как успешные проверки и не выдаёт общий PASS.

## Проверка И Откат

```powershell
flutter test --no-pub test/on_device_diagnostics_test.dart
python -m unittest tooling.test_analyze_device_diagnostics -v
```

Чтобы отменить запись, выключить переключатель. Это не отключит VPN и не
удалит уже накопленный отчёт. Откат APK делать только после экспорта:
прежняя версия не содержит интерфейса выгрузки нового журнала.

Основания: [ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo),
[системный выбор документов](https://developer.android.com/training/data-storage/shared/documents-files),
[Doze и App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby).
