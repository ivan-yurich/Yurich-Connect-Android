# Yurich Connect Android 1.0.128-test.20261007.9

Тестовый prerelease для телефона. Публикация: 8 октября 2026 года.
Проверки устройства: 7 октября 2026 года. GitHub-канал, ARM64, versionCode `43150`.

> Это кандидат для добровольного тестирования, а не стабильная версия.
> Остались отказы готовности Hysteria2/Reality. Стабильный телефонный релиз
> 1.0.127 и отдельный TV preview не заменяются.

## Что Изменилось

- Счётчики новой сессии больше не получают отложенную статистику предыдущего
  подключения. Повторное событие Started не сбрасывает базу измерения.
  Сбросы внутренних счётчиков нормализуются; итог внутри сессии не уменьшается.
- Перед заменой VPN-процесса проверяется фактическое завершение предыдущего
  PID вместо фиксированного ожидания 1,8 секунды. Проверка ограничена по времени;
  неизвестное состояние процесса не выдаётся за успешное завершение.
- Вход в Hysteria2 и выход из использовавшего его процесса изолируются новым
  нативным процессом. Для быстрого переподключения Hysteria2 окно готовности
  увеличено с 24 до 40 секунд, как при холодном запуске; сохранены два
  ограниченных запуска в общем бюджете 65 секунд и подтверждённая остановка.
  Эти меры не устранили все наблюдавшиеся отказы QUIC.
- Давление watchdog-восстановления сохраняется между перезапусками для той же
  конфигурации. При повторных отказах пауза увеличивается от 90 секунд до
  15 минут; сброс требует десяти минут наблюдаемого здорового соединения.
  Ручное переподключение доступно, для смены физической сети есть ограниченное
  раннее восстановление.
- После подтверждённого восстановления убирается устаревшее сообщение об
  остановке. Ошибки чтения диагностики, ранняя остановка записи и разные виды
  восстановления теперь различаются.
- По сравнению со стабильной телефонной версией доступны опциональная
  семидневная локальная диагностика с ручным ZIP-экспортом и технические названия
  протоколов: Reality, NaiveProxy, Hysteria2 и XHTTP. Запись включается пользователем,
  не запускается при установке и не означает пройденный семидневный тест.

Форматы подписок, профилей и внешнее API не изменены. TLS-проверки и критерии
нативной готовности не ослаблены. Постоянные QA-сервисы в APK не добавлены.
Общие нативные исходники используются и TV-вариантом, но опубликованный TV APK
остаётся прежним; новая TV-сборка требует отдельной проверки.

## Проверки

Физическое устройство: HONOR ELP-NX9, Android 16. Телефон подключён к USB и
заряжался. В итоговой матрице проверены четыре типа протоколов, 16 сценариев
на LTE и 16 на Wi-Fi. Один успешный сценарий требовал правильного профиля,
готового runtime, трёх внешних HTTPS-ответов и роста счётчика.

| Проверка | Результат |
| --- | --- |
| Flutter | 187 тестов прошли |
| Android / Kotlin | 156 тестов, без ошибок; нативные исходники после проверки не менялись |
| Offline analyzer диагностики | 7 тестов прошли |
| Flutter analyzer | Замечаний нет |
| APK | Подпись и контрольная сумма проверены |
| Итоговая матрица переключений | 27/32, LTE 13/16, Wi-Fi 14/16 |
| HTTPS внутри матрицы | 81/96; неуспешные сценарии не исключены |
| NaiveProxy / XHTTP в матрице | По 8/8 успешных сценариев |
| Chrome на телефоне | 8/8: четыре типа протоколов на LTE и Wi-Fi |
| XHTTP LTE → Wi-Fi без открытия UI | Первый подтверждённый HTTPS новой сети примерно через 10,5 с |
| XHTTP Wi-Fi → LTE без открытия UI | Первый подтверждённый HTTPS новой сети примерно через 3,0 с |

Матрица использует HTTPS через локальный mixed proxy нативного runtime;
она сама по себе не доказывает прохождение через Android TUN. Отдельные
Chrome-проверки выполнялись обычным браузером через системный VPN, со свежими
уникальными URL и проверкой ответа, TLS и runtime до/после запроса.

Основной UI-процесс не менялся в итоговой матрице. В квалифицированных снимках
PSS VPN-процесса составлял примерно 51,1-65,1 MiB, температура батареи 41-44 °C.
Это выборочные измерения, не оценка автономности или доказательство отсутствия
утечки памяти. CPU, длительный Doze и работа только от батареи не профилировались.

## Известные Ограничения

- Пять сценариев финальной матрицы не достигли готовности: два Hysteria2 на LTE,
  два Reality на Wi-Fi и один Hysteria2 на Wi-Fi. Последующие успешные запуски
  и браузерные проверки не отменяют эти отказы.
- Изоляция Hysteria2 и увеличение таймаута не доказали устранение проблемы.
  Причина отказов QUIC/TCP требует журналов именно неуспешного запуска;
  контроль другим клиентом в той же сети не проводился.
- В ограниченной истории Android exit-info: 14 EXIT_SELF и два SIGKILL
  (SIGNALED, status 9). EXIT_SELF согласуется с предусмотренной заменой процессов;
  причины SIGKILL не установлены. Нельзя без доказательств считать их штатной
  очисткой, OOM или падением ядра.
- В сохранённых записях текущего окна не найден CRASH/CRASH_NATIVE/ANR,
  но ограниченные exit-info и logcat не гарантируют отсутствия любых падений.
- XHTTP остаётся экспериментальным; переключение LTE → Wi-Fi даёт заметную
  паузу. Сокращение ожидания PID не доказало существенного ускорения всего перехода.
- UID fallback включает служебный трафик. Счётчики интерфейса приблизительны
  и не предназначены для биллинга.
- Не подтверждены стабильность 24/7, все серверы и операторы, все прошивки,
  отсутствие любых DNS-запросов вне VPN или готовность к Google Play.

Следующий этап: защищённые журналы до Started, разбор последовательности
Hysteria2 → Reality и причин SIGKILL, исправление воспроизводимых отказов.
Длительный прогон имеет смысл после этих исправлений.

## Разработка И Откат

Команды из каталога проекта при настроенных Flutter, Android SDK и JDK 17:

```powershell
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
.\android\gradlew.bat -p android :flutter_singbox_vpn:testReleaseUnitTest
flutter build apk --release --flavor github --target-platform android-arm64 --split-per-abi --build-name 1.0.128-test.20261007.9 --build-number 41150 --no-pub
```

`--build-number 41150` вместе с существующим смещением GitHub flavor даёт
Android versionCode `43150`. Нужны локальный keystore и `android/key.properties`;
собственная подпись не заменит официальный APK поверх установленного приложения.
Ключи, пароли, `.env`, подписки и личные журналы нельзя публиковать.

Android обычно не устанавливает меньший versionCode поверх большего. Для отката
без потери данных нужно собрать предыдущие известные исходники тем же ключом
с versionCode выше `43150`, например GitHub `--build-number 41151` даёт `43151`.
Делайте это в отдельном чистом рабочем дереве, не сбрасывая локальные изменения.
Не удаляйте приложение ради отката без безопасной резервной копии профилей.
