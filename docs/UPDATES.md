# Обновления Android

## Каналы

- GitHub / стабильный: только опубликованные стабильные телефонные релизы.
- GitHub / тестовый: сборки `1.0.x-test.YYYYMMDD.N` с обновлятором начиная с `.10`
  проверяют опубликованные тестовые и более новые стабильные телефонные релизы.
- TV: отдельные APK и релизы, ручная установка.
- Google Play: обновления через магазин; внешняя установка из приложения выключена.
- Soak: обновления выключены для воспроизводимости длительного теста.

Старые клиенты, включая `.9`, не видят тестовые релизы. Первый переход в тестовый
канал требует ручной установки официального APK с той же подписью поверх
приложения. Не удаляйте приложение и не очищайте профили ради обновления.

Автоматически проверяется наличие обновления при запуске/возврате в приложение,
не чаще одного раза за шесть часов в рамках процесса. Скачивание начинается
по нажатию пользователя. Установку подтверждает Android; скрытой установки нет.

## Диагностика

1. Запишите полную версию, Android versionCode и канал из настроек приложения.
   Сравните именно с телефонным релизом в этом канале, не с TV и не с коммитом.
2. Если этот APK уже установлен, повторное обновление на ту же версию не нужно.
   При переходе со stable нельзя ожидать автоматического получения prerelease.
3. При ошибке сети повторите ручную проверку на другой доступной сети. GitHub
   API может быть недоступен или ограничен по частоте запросов. Токен GitHub
   не нужен и не должен добавляться в приложение. APK хранится на GitHub:
   доступность JSON-метаданных сама по себе не гарантирует доступность скачивания.
4. Сообщение о неизвестной архитектуре означает, что проверка не выполнена.
   Перезапустите приложение; нельзя автоматически выбирать чужую ABI.
5. После запроса Android разрешите установку из Yurich Connect, вернитесь в
   приложение и повторите установку. Запрос разрешения не означает установку APK.
6. Если установщик закрывается, нужны полный текст ошибки и логи `YurichUpdater`,
   `PackageInstaller`, `PackageManager` и ActivityTaskManager. Не очищайте logcat
   до сбора. Подписки, UUID, пароли и необработанные логи не публикуйте в Issues.

Начиная с `1.0.131-test.20261023.1` общий лимит ручной проверки
составляет 60 секунд, автоматической - 26 секунд; отдельного источника метаданных
- 12 секунд. По истечении лимита его запросы и повторы прекращаются. Загрузка APK
имеет отдельные, более длинные тайм-ауты. Ограничения не относятся к стабильной
`1.0.127` или `.10`, пока новый код не установлен на устройство.

Обязательные проверки перед установкой: package `online.dnsai.ivanvpn`, подпись
установленного приложения, полная версия выбранного релиза и строго возрастающий
versionCode. Несовпадение нельзя обходить отключением проверки подписи.

## Проверка И Откат

Команды из корня проекта:

```powershell
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --release --flavor github --target-platform android-arm64 --split-per-abi --build-name 1.0.131-test.20261023.1 --build-number 41157 --no-pub
```

Этот ARM64 split имеет versionCode `43157`. Публикация нового APK не меняет
поведение старого APK без установки. Не объявляйте тестовый кандидат стабильным
только для обхода правил `releases/latest`.

Для отката без потери данных пересоберите предыдущие известные исходники в
отдельном рабочем дереве тем же ключом с versionCode выше установленного.
Например, ARM64 `--build-number 41158` даёт `43158`, выше кандидата `43157`.
Не сбрасывайте чужие изменения и не удаляйте приложение ради отката.

Проверка обновления на конкретном телефоне требует установки новой сборки,
успешного запроса, загрузки и подтверждения системного установщика. Успешные
тесты на компьютере не заменяют эти шаги и не доказывают стабильность VPN 24/7.
