# Проверка серверов и задержки

При подключённом VPN проверки идут через текущий туннель; настройки системного
Always-on/lockdown не отключаются. Без VPN прямой замер доступен только с явного
согласия и при выключенном Kill Switch. Сервер увидит обычный IP телефона.
Без нужного разрешения или при включённой защите прямых проб нет.

## Что означают статусы

| Статус | Что подтверждено |
| --- | --- |
| `TLS N мс · VPN` | Через локальный прокси и текущий туннель завершён TLS handshake с проверкой сертификата по SNI профиля. |
| `HTTPS N мс · VPN` | Активный UDP-профиль доставил HTTPS-запрос до контрольного сайта с ожидаемым статусом. |
| `UDP: подключитесь` | Неактивный Hysteria/Hysteria2 нельзя проверить TCP-пробой; требуется подключение. |
| `TLS не подтверждён` | TLS-проба не подтвердилась. Возможны особенности Reality, частный CA, pin или несовпадение SNI; профиль не объявляется offline. |
| `Нет ответа · VPN` | Проба не завершилась. Причина может быть в текущем туннеле, сети, TLS frontend или сервере. |
| `offline` | Только явная пометка offline/офлайн в имени; такой профиль не проверяется. |

Это **не ICMP ping и не прямая задержка до VPN-сервера**. TLS frontend может
отвечать, даже если ключи VPN неверны; ответ CONNECT 200 сам по себе ничего
не подтверждает. Работу протокола проверяют отдельным подключением и реальным
трафиком. HTTPS-задержка активного UDP-профиля включает путь до контрольного сайта
и не сопоставима напрямую с TLS-задержкой другого профиля.

В списке профилей кнопка обновления проверяет серверы партиями до четырёх.
Каждая TLS-проба имеет общий deadline 8 секунд и лимит CONNECT-заголовка 8 КиБ.
Успех кэшируется на 10 минут, неопределённый результат — на 30 секунд.
На смене сети, VPN-сессии или профилей кэш сбрасывается и сокеты закрываются.
Сырые ошибки, адреса, SNI и ответы серверов в результатах диагностики не сохраняются.

## Реализация и границы

- `lib/src/services/proxy_server_probe.dart`: единственный TCP destination —
  числовой loopback; удалённое имя передаётся в CONNECT. TLS выполняется на уже
  открытом сокете, без отдельного DNS lookup и без отключения проверки сертификата.
- `lib/src/screens/home_screen.dart`: привязка к поколению сессии/сети, ограничение
  параллелизма, нейтральные статусы и отдельная HTTPS-проверка активного UDP-профиля.
- `sing_box_config_builder.dart`, `xray_config_builder.dart`: локальные служебные
  inbound направляются только в proxy до Smart Route и private bypass.
  Непрозрачные пользовательские raw-маршруты не используются для такой диагностики.
- `XrayBootstrapResolver.kt`, `XrayBootstrapPlan.kt`, `BoxService.kt`:
  ограниченное разрешение **только транспортного upstream** перед запуском Xray.
  Это необходимый bootstrap самого VPN, не прямая проба других профилей.
  Применяется физический Android Network, общий тайм-аут 6 секунд и отмена.
  Исходная конфигурация не переписывается; SNI, Reality и HTTP identity сохраняются.
- `RuntimeKillSwitchPolicy.kt`: DNS fallback в Xray выбирает защищённые DNS-клиенты,
  а не разрешение выходить напрямую. В строгом Xray runtime нет localhost DNS:
  транспортный upstream разрешается до запуска нативно, а DoH идёт через proxy.

Проверка служебного прокси не изменяет маршрутизацию обычного трафика TUN.
Smart Route с direct-исключениями по-прежнему **не применяется в строгом kill switch**.
Сохранённые пользовательские настройки не удаляются.

Семантика использованных API: [TLS на существующем сокете без DNS lookup](https://api.dart.dev/dart-io/SecureSocket/secure.html),
[выбор DNS-клиентов Xray 26.6.27](https://github.com/XTLS/Xray-core/blob/v26.6.27/app/dns/dns.go).

## Проверка и откат

После установки поверх приложения с той же подписью проверить все используемые
протоколы на Wi-Fi и cellular, переключение сетей, обновление статусов и отсутствие
ложного offline. Положительный результат без туннеля недопустим.

Откат выполняется без удаления приложения и без очистки данных: восстановить
затронутые исходники из сохранённого перед работой snapshot, собрать с той же
подписью и **versionCode выше установленного**, затем установить поверх.
Не понижать защитные настройки Android и не применять uninstall/clear для отката.
Короткий функциональный прогон не является подтверждением работы 24/7.
